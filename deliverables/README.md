# Collected deliverables

Start with the [gallery](index.html), [completion checklist](CHECKLIST.md), or [data-spec audit](reports/data-spec-audit.md).

The primary dataset is **ten variants of the home kitchen: three full RGB-D and seven state/range/IMU runs**, 60 simulated seconds each. Every variant has fal materials/clutter, visual previews, a Cycles still and a matching recorded dataset/video. The five commercial-kitchen and five warehouse variants are supplementary.

Intermediate attempts, superseded copied captures, duplicate build assets, Blender working files and regenerable render inputs are excluded. Portable archives contain the resources needed to load the scenes. The original repository baselines remain available for provenance; code, inputs, accepted-seed factors and rejection reports explain reproduction. Variant 008 uses seed 1308 after seed 308 failed robot-access checks; validation was not weakened.

`code/` contains maintained documentation and source, including the collection helpers. The original brief is retained under `reports/`; private development notes are not prerequisites. Follow `code/docs/running.md` for setup and cached-asset requirements. Reusing saved scenes needs no hosted call; regenerating missing fal downloads may cost money. No credentials, Git metadata, Python environment or vendor binary/cache tree are packaged. Asset provenance and licenses remain with the assets.

The manifest records the source snapshot's Git revision and current file hashes. Artifacts span development revisions; that revision is not a claim that every artifact was generated by identical code. Earlier collection checks/costs are explicitly historical in `reports/history/`. Cold-machine installation timing, unseen-prompt evaluation and complete historical provider billing remain unverified; see the checklist.
